Prisma generado y backend compilado; 19 migraciones disponibles, ninguna pendiente.
H6/H7/H8/H9/H23: 86 pruebas aprobadas. Unitarias backend: 25.
Integración general: 109 comprobaciones HTTP aprobadas. H23 sobre Docker: 24 pruebas aprobadas.

Flujos completos comprobados mediante HTTP:
1. Cliente crea TAKEAWAY, genera cuenta y paga con tarjeta simulada aprobada.
2. Cocina toma pedido, marca platillos, mesero recoge y confirma entrega.
3. Cliente consulta elegibilidad y registra reseña; duplicado devuelve 409.
4. Mesero crea DINE_IN, emite código y cliente confirma vinculación.
5. Cocina y entrega completan el pedido; cliente registra reseña y otro cliente recibe 404.
Antes de DELIVERED, la reseña se rechaza incluso si el pedido ya está READY o OUT_FOR_DELIVERY.
En estos dos recorridos no se escribe DELIVERED directamente en la base.
Las pruebas aisladas de límites/errores sí usan fixtures para estados y fechas específicos.
Se conserva el límite inclusivo de 720 horas UTC, permisos y protección contra duplicados concurrentes.
La limpieza elimina únicamente registros temporales de las pruebas, incluyendo auditorías, pagos y recibos.

Reproducir desde la raíz con Docker activo:
 npm ci
 npm start
 npm run prisma:generate --workspace backend
 npm run build --workspace backend
 H23_API_URL=http://127.0.0.1:3000/api node backend/scripts/run-qa.cjs npm run test:h23 --workspace backend
El ejecutor QA exige base local con nombre terminado en _test.

Postman: importar H23-Reviews.postman_collection.json y seleccionar environment con cuentas e IDs válidos.
Preparar pedidos propios mediante H7, H8 y H9; para TAKEAWAY pagar antes de cocina.
Para pedidos de mesero, vincular por código al cliente que reseñará.
Colecciones preparadas; no ejecutadas en Postman/Newman.
